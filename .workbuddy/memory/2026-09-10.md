## 补充（同日 15:50）：峰谷定价的展示口径标记

**问题**：DeepSeek 官方 V4.1 Flash 有峰谷两档，看板上显示的是哪一档？需要标出来。

看板早已统一按**高峰档**展示/对比（`index.html` 的 `officialFor()`），只是标记不完整。

**改动（`index.html`，纯展示层，不动数据）**：

- 综合比价视图「官方基准」行：加 `<span class="tag tag-warn">峰值</span>` 标记，备注列给出 `空闲 ¥1.00/¥4.00`

- 提供商视图官方表备注：`峰谷定价(按峰值)` → `峰谷定价(按峰值) · 空闲 ¥1.00/¥4.00`
- 标记说明行补一条峰值图例

**同时纠正一个此前的误判**：`compositePrice(price, official)` 与 `effectiveInput(price, official)` 的第二个参数
**声明了但从未使用**（`official` 是死参数）。所以第 302/330 行传 `DATA.officialPrices[m.id]`（空闲）还是
`officialFor(m.id)`（峰值）**结果完全相同**，不存在数值不一致。原以为的「bug」是假的 —— 读函数体才发现。
→ 教训：**别只看调用点就断言不一致，必须读被调函数的实现**。

**验证**：`node --check` 语法通过；抽出页面真实函数（非副本）跑断言 5/5 通过：
`<峰值>` 标记 ✓、`空闲 ¥1.00/¥4.00` ✓、`vs 官方(峰)` ✓、provider 视图峰谷+空闲 ✓、其它模型未误标 ✓。
（无头 Chrome 截图在本沙箱被 SIGTERM 拦掉，改用 DOM 桩离线渲染验证。）

**顺带发现**：以高峰为基准时，`deepseek-v4.1-flash` 的「最优提供商」是 **DeepSeek 官方空闲档（34%）**，
而非 aihubmix（37%）。空闲档 = 官方峰值的一半，天然比第三方便宜。这会让最优列出现官方自营 —— 逻辑正确，
但用户不一定总能挑在空闲时段用。

**环境坑（本会话，已定位根因）**：本会话 shell 里的 `grep` 是 WorkBuddy 的 **brokered shim**
（`command -v grep` → `.../cli/vendor/shim/brokered-bin/grep`）。它**不支持 BRE 交替 `\|`**：
`grep -n "空闲\|高峰" data.json` 返回 **rc=1（误判为无匹配）**，而 `grep -n 空闲 data.json` 正常返回 3 行。
我因此两次把"有匹配"读成"不存在"。→ 规则：**shell 里别用交替式 grep，要么单模式分开跑，要么用 Grep 工具**；
任何"没搜到"的结论都要换一种方式复核再采信。
